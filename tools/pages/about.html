About

What Broiler is

A browser, a word processor and a code editor — plus the platform underneath them, which is the actual project. Everything is open source, and everything was written from scratch rather than wrapped around somebody else's engine.

The short version

Almost every "alternative browser" you can download is Chrome underneath. The window dressing changes; the engine that turns a web page into pixels is the same one Google maintains. The same is true across software generally — a handful of large engines do the actual work, and everything else is a shell around them.

Broiler is an attempt to build the whole stack again, in the open, in a language you can read — and then to prove how far it got, honestly, including the parts that fall short.

The visible result is three applications. The real project is the layer beneath them: a set of independent building blocks — a rendering engine, a layout engine, a UI toolkit, image and document handling, a JavaScript engine — that any .NET program can use.

The three apps

Browser

Loads and renders real websites with its own engine, its own layout and its own JavaScript.

Writer

Writes and formats documents, and opens the Word, RTF, HTML and Markdown files you already have.

Code

Edits C#, checks it as you type, builds it — and records what a person has reviewed.

Why do it this way

Written in managed .NET, not C++

Browser engines are traditionally written in C++, where a mistake with memory is a security bug. Broiler is written in C# on .NET, where the runtime prevents whole classes of those mistakes outright. That is not a claim that Broiler is secure — plenty of other things can still go wrong, and this preview has had no security audit — but it removes a category of problem by construction rather than by care.

It also makes the code readable by far more people. If you can read C#, you can read how this browser decides where a paragraph goes.

One platform, three apps, four kinds of machine

The word processor and the code editor are not separate products that happen to look similar. They are the same application framework with different content in it. That is why a dialog behaves identically in both, and why adding a platform means writing a thin adapter rather than a new app.

How it is made

Broiler is a small project — one maintainer — and it says openly that a large share of the code was written by AI coding tools working under that maintainer's direction. The maintainer decides what to build, reviews changes, runs the tests, drives refactors and pays for the inference.

Why that is stated so prominently

Because it changes what you should assume. AI can produce a great deal of plausible code quickly, and plausible is not the same as correct. So rather than claiming the code is reviewed, the project built a tool that records what a person has actually read — file by file, against a fingerprint of the exact text they read, so an approval expires when the code changes underneath it.

Today that number is honest and unflattering, and it is published anyway. How review is recorded →

The same instinct runs through the rest of the project. Test results are published with the failures included. Where a measurement is missing, the documentation says it is missing rather than leaving a gap you might read as a pass.

The name, and the chicken

A broiler is a chicken raised for meat. The project runs with the joke: the components ship with cartoon-chicken artwork, and the acronym came afterwards — Browser Infrastructure in Intermediate Language with Enhanced Reliability. "Intermediate language" is the .NET part: the JavaScript engine compiles your scripts into the same instruction set the rest of .NET runs on.

Standing on other people's work

Broiler did not start from nothing, and it names what it started from.

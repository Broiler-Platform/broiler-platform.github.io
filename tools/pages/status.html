Where Broiler actually stands

Early preview. The apps run and do real work, and three of them can now be downloaded as previews — but nothing here should be trusted with anything that matters. This page says why, in detail, without the usual softening.

Can I download it?

Three of the apps, as early previews — read the small print first.

Since 22 September 2026 the project has published preview builds of the Writer and of Plate as GitHub pre-releases, and since 30 September 2026 of the Browser. Each describes itself as "a preview build for evaluation and testing, not for production use". There is still no installer: the desktop downloads are single files you unzip and run, and the Android one is a package you install by hand.

Unsigned means Windows SmartScreen may warn you before the first start, and that nothing but GitHub vouches for where the file came from.

These previews went out ahead of the project's own release plan

The project's roadmap says a release should come from an exact commit that has passed human, dependency, licence, static-analysis and vulnerability review, should build reproducibly, and should be signed. None of that is recorded for any of the three previews: the Browser's review record is a pending summary rather than a review of its code, the Writer has no human-review record at all, Plate's reads pending with nothing reviewed, and the Writer's latest preview was published from a version whose automated tests were failing. Use them to look around, on copies of files that do not matter.

What works today

Browser

  • Loads real websites and renders them with its own engine
  • Address bar, back, forward, reload, stop, home
  • Favourites
  • Forms — text fields, checkboxes, radio buttons, drop-downs, file pickers
  • Runs the page's JavaScript
  • Cookies, while the browser is open
  • Images, and video on Windows
  • Forgets every cookie when you close it
  • No tabs, extensions, sync, bookmarks import or password manager
  • No video calling, WebRTC or WebSockets

Writer

  • Open, edit and save DOCX, ODT, RTF, HTML and Markdown
  • Tables, headers and footers in those files are shown
  • Open PDFs for reading, with their pictures, on Windows and Linux
  • Bold, italic, underline, strikethrough, fonts, colours
  • Alignment including justify, lists, indenting, page breaks
  • Insert pictures; zoom from 25 % to 400 %
  • Reveal-codes view showing exactly what formatting is where
  • Undo, redo, cut, copy, paste, and a prompt before unsaved work is lost
  • No creating tables, footnotes, track changes, spell check or mail merge

Code

  • Open a folder or solution; browse and edit files
  • C# syntax colouring, and live errors and warnings
  • A Problems list you can click through
  • Build, rebuild, publish, cancel
  • A review pane that records what has been read, per file or per declaration
  • C# only — no other languages, no extensions marketplace
  • No debugger
  • Its current source does not build in the project's automation

Plate

  • Opens RTF, DOCX, HTML, Markdown and PDF documents
  • Opens PNG, JPEG, GIF, BMP, TIFF and WebP pictures
  • Zoom, fit to window, select and copy
  • Read-only — no editing or saving, by design
  • One file at a time; no panning around large pictures
  • Windows only

Mail

  • One IMAP account, password kept in Windows Credential Manager
  • Receive and read mail as plain text
  • Writing, replying and sending — newly landed, tested only against the project's own test servers
  • No attachments, folders, search or HTML mail
  • Mail is not kept between runs
  • Not tested with any real mail provider; Windows only

How good is the browser, really?

Better than you would guess and worse than a shipping browser — and unusually, the project measures it rather than asserting it.

It renders Wikipedia, GitHub, MDN, Hacker News, heise and W3C at a fixed window size and compares every pixel against Chrome. One worked example: mediawiki.org started at 38.9% of pixels matching Chrome and, after fixing roughly twenty underlying engine bugs found that way, reached 82.7%. That is a real measurement of a real page, not a marketing number — and the remaining 17% is written up too.

Against the web's official test suites the picture is the same shape: a lot passing, a documented tail that is not. There are 51 known rendering gaps still open, each with an owner and a description of what is missing.

Expect broken pages

Sites that lean hard on very recent CSS, on video calling, or on aggressive bot detection will misbehave or fail outright. That is expected at this stage.

Is it safe to use?

Treat it as a preview, not as a browser for your bank.

  • No security audit has been done. No fuzzing campaign, no dependency scan, no independent review is recorded for any component.
  • The JavaScript engine is not a sandbox. It does not claim to isolate a hostile web page from the machine the way a mature browser does.
  • Most of the code has not been read by a person yet. The project tracks this precisely, and the number is currently very low.
  • There is no privacy problem in the sense of data collection — no accounts, no telemetry, no sign-in — but that is not the same as being hardened against hostile websites.

Practical advice: browse ordinary public pages with it, open your own documents in it, and do not use it for anything sensitive. The full safety statement →

Platform by platform

PlatformStateCaveats
Windows Most complete The best-developed path. Hardware-accelerated drawing, real system windows for dialogs, video playback. The only platform Plate and Mail run on.
Linux Working preview Runs, but much of the drawing still goes through the processor rather than the graphics card, so it is slower. Dialogs stay inside the main window.
Android Emulator only Browser and Writer build and run on an emulated Android 16 device. The Writer preview includes a signed package you can install on a phone, but nobody has verified the apps on a physical phone yet.
In a web browser Paused The Writer was built to run inside another browser as a web app, but since 14 September that version is not being built while it moves onto the platform's new packages, and no preview includes it. The Broiler Browser does not run this way — a browser engine inside a browser is a separate project.
macOS Not started Needs native windowing, graphics, input, signing and notarization work first.

What has to happen before a release you can trust

The previews above skip most of this list. The project's roadmap still sets it as the bar for a real release:

  1. Human review of the release code. An exact commit, reviewed by a person — along with its dependencies, licences, static analysis and known vulnerabilities. For every app that gate is still red.
  2. Reproducible packaging. Building the exact reviewed version twice has to produce byte-identical packages, and installing them on a clean machine has to work.
  3. Signing. Release keys, a signed manifest format, and a documented owner for updates on each platform. Only the Android packages are signed today.
  4. A published smoke test. Proof that the thing you downloaded actually starts and works on the systems it claims.

Only after that does an installer appear, and automatic updates come later still — the project's stated order is signed portable releases first, an updater afterwards. The full roadmap, with exit conditions →

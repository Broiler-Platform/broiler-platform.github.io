For developers

Components

Eighteen components, released independently

Every reusable part of Broiler is its own repository, with its own solution, its own CI and its own NuGet packages — Broiler.Layout, the last one that lived inside another repository, has had its own since September 2026. An application takes the pieces it needs as packages; nothing is bundled by default, and no abstraction ever references an implementation.

Independent preview versions

Component packages are published to nuget.org only, as prereleases, so every install needs --prerelease. They are no longer versioned in lockstep: each repository's publish workflow resolves its own next unused 0.1.0-preview.N, and eng/Broiler.Packaging.props is now a floor rather than the version. Consumers pin what they built against — Graphics at preview.7, Media at preview.14 and Documents at preview.21, for example — so there is no single suite version to quote. The applications are not published as packages.

Shared component constraints

Every component repository holds itself to the same set of rules. They are not aspirations — several are asserted by architecture tests that fail the build.

Target .NET 10

No compatibility shims for older runtimes. Platform assemblies target net10.0-windows only where they must. One exception: Broiler.Unicode's three packages target both net8.0 and net10.0.

No third-party runtime dependencies

Image codecs, PDF syntax, regular expressions, Unicode data, networking and the JavaScript engine are implemented in Broiler's own repositories. Test tooling may use external packages; shipping assemblies may not. Broiler.Net bundles the Public Suffix List as data, under MPL-2.0.

Trimming- and AOT-friendly, safe code

Abstraction assemblies are platform-neutral and safe-code compatible. The Writer's desktop heads publish with NativeAOT and report zero IL2xxx/IL3xxx warnings — which is only possible because nothing in the closure needs reflection AOT cannot see through.

Explicit composition, no hidden globals

There is no process-wide mutable codec registry and no module-initializer side effect. An application builds one immutable catalog at its composition root and passes it in.

Where the newer components came from

Most of the seven without a page here are not new code. Three used to ship inside Broiler.JS as nested submodules — Broiler.DateTime, Broiler.Regex and Broiler.Unicode — and have been promoted to top-level repositories and aggregate submodules of their own. Broiler.JS now takes Regex and Unicode's CLDR locale data as nuget.org packages, and no longer references DateTime at all.

Open source · Early preview

Three everyday apps, built from scratch.

Broiler is a web browser, a word processor and a code editor — all built on one platform written from the ground up in .NET. Same look, same behaviour, whether you run them on Windows, Linux, Android or inside another browser.

The apps

What you can actually run

Three finished-shaped applications, not demos. They share one toolkit, one renderer and one set of file handling — so a habit you learn in one carries into the next.

Broiler Browser

Browse the web: type an address, follow links, go back and forward, fill in forms, keep favourites. It renders real pages — Wikipedia, GitHub, MDN — with its own engine, not a copy of someone else's.

WindowsLinuxAndroid

Broiler Writer

Write and format documents, and open the files you already have — Word documents, RTF, HTML and Markdown, plus PDFs for reading. Includes a reveal-codes view that shows exactly what formatting is where.

WindowsLinuxAndroidIn a browser

Broiler Code

A C# editor with syntax colouring, live error checking and a build button. It also carries a review workspace that tracks, file by file, what a person has actually read.

Where it stands

Honest answer: not ready for you yet

Broiler is an early preview. The apps run, and they do real work — but there is no download to click yet. Nothing has been packaged, signed and released for people to install, and nothing here has been through the safety review the project requires before it says otherwise.

If you are a developer, you can build and run all three today. If you are not, the useful thing to do is watch the project — or help fund it.

Why bother

Why build all this from scratch?

No borrowed engine inside

Most alternative browsers are a shell around Chromium. Broiler's page engine, layout, text rendering and JavaScript are its own code — so it is genuinely a different implementation, not a reskin.

One app, many machines

The same application code runs on Windows, Linux, Android and inside a web browser. Only a thin layer at the bottom changes, so behaviour does not drift between them.

Small and self-contained

The desktop Writer compiles to a single 9.2 MB file that runs with nothing else installed — no runtime to download first, no folder of 162 files.

Readable, checkable code

It is written in managed .NET rather than C++, and every safety-relevant boundary is written down. The project publishes what it has not verified as plainly as what it has.

Free, and free to fork

Apache-2.0. Every part of it is public, including the parts that are unfinished, the failing tests and the open bugs.

Your files stay yours

Documents open and save in the formats you already use. There is no account, no cloud, and no sign-in anywhere in any of the three apps.

Under the hood

Built out of parts, each of which does one job

The apps are assembled from a set of independent building blocks. You never need to think about them — but they are why one browser, one word processor and one editor can share so much. (Yes, the project's mascot is a chicken. A broiler is a chicken.)

Questions

The things people ask first

Is it free?

Yes, and it always will be. Broiler is open source under the Apache 2.0 licence. There is no paid edition, no subscription and no account.

Can I install it today?

Not yet. There is no released, signed installer — the project has not finished the review and packaging work that has to come first, and it would rather say so than hand out something unreviewed. Where it stands →

Will it replace Chrome or Word?

Not today, and that is not a near-term goal. Broiler renders many real websites well and opens most everyday documents, but a mature browser and a mature word processor represent decades of work. This is a preview of a genuine alternative implementation, not a finished product.

Does it send anything anywhere?

The apps have no accounts, no telemetry and no sign-in. The browser obviously fetches the pages you ask it for. On Android, only the Browser is allowed to use the network at all, and unencrypted connections are switched off in both apps.

Who makes it?

A small project run by one maintainer, with a lot of the code written by AI tools under their direction — which the project states openly, and backs with a review system that records what a human has actually read. How it is made →

How can I help?

Try building it and report what breaks, or sponsor the project — the maintainer pays for the AI inference and the testing time personally, so funding directly moves it along.

Are you a developer?

Everything is on GitHub, and the platform ships as reusable .NET packages: a layout engine, a UI toolkit, image codecs, document codecs, a JavaScript engine. Start with the developer overview — it maps the whole thing in one page.

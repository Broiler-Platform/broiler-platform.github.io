App

Broiler Code

A C# editor built on the same platform as the Writer — and the tool the project uses to keep itself honest about which code a human has actually read.

Windows Linux Early preview

What it does

  • Open a folder or a solution and browse it in a file tree
  • Edit C# with syntax colouring
  • Errors and warnings as you type, from the real C# compiler
  • A Problems list you can click to jump to the line
  • New file, new project
  • Save, save all, save as
  • Build, rebuild, publish and cancel a running build
  • Tabs for open documents
  • Undo, redo, find your way around with the keyboard
  • The Human Review pane — see below

Scope for this preview is C# on .NET 10 with standard project files. It does not invent its own project format, and it does not write anything Broiler-specific into your .csproj.

The Human Review workspace

This is the part that does not exist in other editors, and it is the reason the app was built first.

A great deal of Broiler was written by AI tools. The usual way to reassure people about that is a sentence in a README saying the code is reviewed. That sentence is unfalsifiable, and it goes stale the moment anything changes.

So instead: every source file has a recorded review state, tied to a fingerprint of the exact text that was read.

Mark a file as you read it

Reviewed, in review, needs change, or open question. A file you have not opened has no state, which is itself information.

Approvals expire when the code changes

Staleness is decided by content, not by commit — so rebasing does not wipe your reviews, and reverting a change brings its review back.

Notes that follow the code

A note stays attached to the lines it was written about as they move, and says so when it can no longer find them rather than pointing at the wrong place.

A coverage number that can't flatter

It counts only files approved and unchanged since. Stale approvals are reported separately and never counted.

The records live in the repository next to the code, so review history is part of the project's history — and a pull request can be told which reviews it just invalidated. The same code computes the badge in the editor and the number published by the project's automation, so the two cannot disagree.

What it doesn't do yet

  • Any language but C#
  • A debugger
  • Extensions or a marketplace
  • Refactoring tools, or rename-across-project
  • Git integration
  • Integrated terminal

On each platform

PlatformWhat you get
WindowsThe full editor with live compiler diagnostics and local builds.
LinuxThe same, on X11. Its on-screen text input reports itself as unavailable, and the window has not been exercised much on a real Linux display yet.
Android and the browserPlanned rather than shipped. The design splits "edit code" from "build code" so a phone or a web page can edit and colour C# locally while a build runs elsewhere — and the app is meant to show you which mode you are in rather than quietly behaving differently.

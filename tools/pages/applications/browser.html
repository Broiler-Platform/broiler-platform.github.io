App

Broiler Browser

A web browser whose engine is its own code, top to bottom — the HTML parser, the layout, the text rendering and the JavaScript. Not a shell around somebody else's.

Windows Linux Android · emulator-tested Early preview

What it does

  • Type an address and load a page
  • Follow links, go back and forward — including links that jump to a spot on the same page
  • Reload, stop, and a home button
  • Keep favourites — a new install starts with six
  • Cookies, so a site can remember you while the browser is open — with the web's usual rules about which site may read which
  • Pages that move you on by themselves: a script redirect, a timed refresh, a form a page submits for you
  • See loading progress, and a clear error page when a site fails
  • Fill in forms — text fields, checkboxes, radio buttons, drop-downs
  • Upload files through a page's file picker
  • Confirmation before re-submitting a form
  • Runs the page's JavaScript
  • Shows images; plays video on Windows
  • Copy and paste to and from other apps
  • Keyboard, mouse and — on Android — touch

What it doesn't do yet

  • Tabs
  • Extensions or add-ons
  • A password manager or autofill
  • Remember anything after you close it — cookies are kept only while the browser is running, so every site signs you out when you quit
  • Cookie settings — no way yet to block third-party cookies or clear them by site
  • Sync, or a Broiler sign-in of any kind
  • History search, or importing bookmarks
  • Video calls, screen sharing or WebRTC
  • WebSockets
  • Private browsing as a separate mode

One consequence you may notice

Some pages deliberately test for video-calling support and print an error to the console when it is missing. That is the page detecting an absent feature and handling it — not the browser crashing. The project has an implementation plan for it and, until that lands, refuses to fake the feature by exposing an API that does nothing.

How well does it render the web?

Better than you would expect, and the project measures it rather than claiming it. Every week it renders Wikipedia, GitHub, MDN, Hacker News, heise, 7-Zip, W3C and MediaWiki at a fixed window size and compares the result with Chrome, pixel by pixel.

38.9 → 82.7 % Pixels matching Chrome on mediawiki.org, before and after fixing the twenty-odd engine bugs that comparison exposed
51 Known rendering gaps still open, each written up with what is missing and who owns it
170 HTML conformance cases in the project's own suite, none quarantined

That MediaWiki number is worth explaining, because it is typical of how this engine improves. The page looked wrong; comparing it with Chrome turned up a calc() bug that broke 25 stylesheet rules at once, floated items escaping their layout, a margin counted twice, and bold and italic text falling back to the regular font. Each fix was a general engine fix, not a patch for that site.

Expect breakage on sites that lean on very new CSS, on video calling, or on aggressive bot detection. How it is all measured →

On each platform

PlatformWhat you get
Windows The most complete version. Hardware-accelerated drawing through Direct2D, native text rendering, and video playback.
Linux Runs on X11 with clipboard and input support. Much of the drawing still goes through the processor rather than the graphics card, so it is slower than the Windows build. No video playback.
Android One full-screen surface with touch, pen, keyboard and international text input, and correct spacing around the system bars. Verified on an emulator only — not yet on a physical phone. Unencrypted http:// pages are blocked, which includes two of the default favourites.

Privacy

  • No Broiler account and no sign-in — the browser keeps one local profile on your machine, and nothing about it leaves it.
  • No telemetry or usage reporting of any kind.
  • Cookies are held in memory only, and are gone when you close the browser.
  • On Android, unencrypted http:// traffic is switched off.
  • Favourites are stored on your machine.

That is data collection, though, not hardening. A browser also has to defend you from hostile pages, and this one has had no security audit — no fuzzing, no dependency scan, no independent review. Its JavaScript engine explicitly does not claim to be a sandbox. Do not use this preview for banking or anything sensitive. The full safety statement →

Getting it

No download yet — the first one is being prepared

A first preview, 0.1.0-preview.1, was built on 30 September for Windows, Linux and Android. It is still an unpublished draft: nobody outside the project can download it until someone reviews and releases it. The draft holds Windows and Linux files that are not code-signed and an Android package signed with the project's release key, and its own notes say to open controlled content only, because the JavaScript engine is not a security sandbox.

Until then you can build it from source, which takes a .NET 10 SDK and one command. How to build →

For developers

Three platform heads over a shared chrome, embedding the HtmlBridge control that binds the DOM, the renderer and the JavaScript engine into one page lifecycle. A plain git clone builds it — every component arrives as a NuGet package.

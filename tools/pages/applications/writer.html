Broiler.Writer

Four platform heads — Windows, Linux, Android and WebAssembly — over a shared Broiler.Writer.Core, plus Broiler.Writer.FormatCodes, the reveal-codes layer that keeps a structured view of the document in sync with the editing surface.

dotnet test  Broiler.Writer.Tests.slnx -c Release

Document formats

Broiler.Writer.Core registers the RTF, DOCX, HTML and Markdown codecs for both opening and saving.

PDF is deliberately not part of the shared set

The Windows and Linux heads register Broiler.Documents.Pdf themselves, for opening only, so that no head acquires the codec transitively. Broiler.Writer.FormatCodes.Tests asserts that this separation holds — the policy is a test, not a convention.

Dialogs are real OS windows

Open, Save As, Insert Picture and Font are real top-level OS windows on the Windows head. Each can be moved onto another monitor, is ordered by the window manager, and carries the one title bar Broiler.UI draws for it rather than a second native caption.

Broiler.UI calls this breaking out and makes it the default for every owned window and dialog. The Windows head supplies the IUiWindowHost capability that makes it possible, in WriterWindowsUiHost, and each broken-out dialog gets its own WriterHostWindow — a second Direct2D window that does not own the message loop, so closing a dialog never quits the Writer.

The Linux, Android and WebAssembly heads do not offer the capability, so their dialogs stay logical subwindows rendered inside the main viewport. That is the documented fallback rather than a failure.

NativeAOT on both desktop heads

The win-x64 and linux-x64 artifacts are a single self-contained native binary that runs with no .NET runtime installed — 9.2 MB for the Windows head, against a 162-file framework-dependent drop.

This works because nothing in the Writer's closure needs the reflection AOT cannot see through. In particular the Direct2D backend dispatches COM through manual vtable offsets and delegate* unmanaged function pointers rather than ComImport interfaces — which is the one pattern that would otherwise rule it out. The Linux head reports zero warnings under the trim, AOT and single-file analyzers.

Keeping it that way is a maintenance rule

Reflection, Activator.CreateInstance, and reflection-based serialization in a head or in Broiler.Writer.Core will break the AOT publish while leaving an ordinary build green. CI publishes both desktop heads with AOT for exactly that reason.

The other two heads are deliberately excluded. Android — the SDK raises XA1040 ("the NativeAOT runtime on Android is an experimental feature and not yet suitable for production use"), and it collides with that head's PublishTrimmed=false since native compilation implies trimming. WebAssembly — NativeAOT emits a native binary for a desktop OS and does not apply; the wasm analogue is mono's own RunAOTCompilation, a separate feature that is not enabled.

Prerequisites

  • .NET SDK 10.0 or later — developed against 10.0.400.
  • Windows head — net10.0-windows, Direct2D.
  • Linux head — net10.0, X11 clipboard and input coordination.
  • Android head — the android workload; net10.0-android36.0, minimum SDK 24, android-arm64 plus android-x64.
  • WebAssembly head — the wasm-tools workload. It publishes trimmed on every publish path; publishing this app untrimmed crashes the mono runtime at boot.

The suppression list was measured, not inherited

Directory.Build.props carries the suppressed-warning list with a documented reason for every code. That list was measured against a clean rebuild of all five solutions rather than copied from elsewhere, and nothing in it is authored in this repository — the nullable warnings come from component submodules and from vendored Android glue, and CA1416 is a false positive against runtime Build.VERSION.SdkInt guards the analyzer cannot see through.

NU1504 is deliberately left visible: the nested Broiler.DOM checkout lists Microsoft.SourceLink.GitHub twice, which is a real upstream defect whose fix belongs in Broiler.DOM. It is the only warning a clean build still emits.

Known issues

  • Some components compile more than once. Broiler.Media and Broiler.Media.Image five times in a desktop head, Broiler.Graphics four times, and Broiler.Input, Broiler.Documents.Model and Broiler.Documents.FormatCodes twice. Assembly-identical, so no reference conflict — but wasted work.
  • The nested Broiler.DOM gitlink is not on main. Broiler.Documents pins its own checkout at a commit off a tokenizer fix branch, while the top-level submodule is on main. Both are checked out, so Broiler.Dom compiles from the older revision when reached through Broiler.Documents.Html. Resolving it means bumping the gitlink upstream.

Continuous integration

Alongside the shared conventions, the WebAssembly job publishes as well as builds — this app must publish trimmed, and only a publish exercises that. The dispatch-only release workflow uploads win-x64, linux-x64, a debug-signed android-arm64 APK and the browser-wasm static site. Pass native-aot: false when dispatching to get framework-dependent output instead.

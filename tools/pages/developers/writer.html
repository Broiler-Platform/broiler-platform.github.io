Application · developer detail

Broiler.Writer

Four platform heads — Windows, Linux, Android and WebAssembly — over a shared Broiler.Writer.Core, which owns the reveal-codes controller that keeps a structured view of the document in sync with the editing surface, plus Broiler.Writer.FormatCodes, the UI-independent projection scheduler beneath it.

No HUMAN_REVIEW record GitHub pre-release 0.1.0-preview.5 4 heads No submodules Apache-2.0

Preview — public GitHub pre-releases, not for production use

Public APIs, repository layout and persisted behaviour are not frozen and may change before 1.0. The document codecs parse untrusted input — RTF control words, Open XML packages, ODT, HTML and PDF object graphs — and must be treated as security-sensitive; no fuzzing campaign, dependency scan or independent security audit is recorded for this repository. Substantial implementation work was AI-assisted, and this repository carries no HUMAN_REVIEW.md, so no checkout or release of it should be described as human-approved. The latest pre-release, 0.1.0-preview.5, was published from a commit whose CI test jobs failed — see Releases.

Getting started

The components the Writer is built on — Documents, DOM, Graphics, Media, Input and UI — are NuGet packages restored from nuget.org, so a plain clone is the whole checkout.

clone, build, run
git clone https://github.com/Broiler-Platform/Broiler.Writer.git
cd Broiler.Writer

dotnet build Broiler.Windows.Writer.slnx -c Release
dotnet run --project src/Broiler.Writer.Windows/Broiler.Writer.Windows.csproj -c Release
dotnet test  Broiler.Writer.Tests.slnx -c Release

The repository's README still says to clone with --recurse-submodules. That is out of date: the tree records no submodule commits. A leftover .gitmodules still names six components, but there is nothing for Git to check out.

Document formats

Broiler.Writer.Core registers the RTF, DOCX, ODT, HTML and Markdown codecs for both opening and saving.

PDF is deliberately not part of the shared set

The Windows and Linux heads register Broiler.Documents.Pdf themselves, for opening only, so that no head acquires the codec transitively. Broiler.Writer.FormatCodes.Tests asserts that this separation holds — the policy is a test, not a convention. Both heads compose three of the codec's optional providers: the JPEG decoder, the sfnt font-program reader and the ICC colour-profile reader.

An opened PDF can be saved in any of the save formats with its pictures. The PDF reader hands them over as decoded pixels and every save format needs an encoded picture, so a save encodes each one as PNG first (WriterPictureEncoding). The document in the editor is not changed.

Dialogs are real OS windows

Open, Save As, Insert Picture, Font and About are real top-level OS windows on the Windows head. Each can be moved onto another monitor, is ordered by the window manager, and carries the one title bar Broiler.UI draws for it rather than a second native caption.

Broiler.UI calls this breaking out and makes it the default for every owned window and dialog. The Windows head supplies the IUiWindowHost capability that makes it possible, in WriterWindowsUiHost, and each broken-out dialog gets its own WriterHostWindow — a second Direct2D window that does not own the message loop, so closing a dialog never quits the Writer.

The Linux, Android and WebAssembly heads do not offer the capability, so their dialogs stay logical subwindows rendered inside the main viewport. That is the documented fallback rather than a failure.

New, Open and File → Exit ask what to do with unsaved edits — Save, Discard or Cancel — using Broiler.UI's existing modal dialog, with no toolkit change. On Linux the window manager's own close button still bypasses it: the current graphics package exposes only a latched close flag, without a way to cancel or reset it.

NativeAOT on both desktop heads

The win-x64 and linux-x64 artifacts are a single self-contained native binary that runs with no .NET runtime installed — 9.2 MB for the Windows head, against a 162-file framework-dependent drop.

9.2 MBWindows head, single self-contained native binary
162 → 1Files, against the framework-dependent drop
0IL2xxx/IL3xxx warnings on an AOT publish

This works because nothing in the Writer's closure needs the reflection AOT cannot see through. In particular the Direct2D backend dispatches COM through manual vtable offsets and delegate* unmanaged function pointers rather than ComImport interfaces — which is the one pattern that would otherwise rule it out. The Linux head reports zero warnings under the trim, AOT and single-file analyzers.

Keeping it that way is a maintenance rule

Reflection, Activator.CreateInstance, and reflection-based serialization in a head or in Broiler.Writer.Core will break the AOT publish while leaving an ordinary build green. CI publishes both desktop heads with AOT for exactly that reason.

The other two heads are not published with NativeAOT. Android — the SDK raises XA1040 ("the NativeAOT runtime on Android is an experimental feature and not yet suitable for production use"), so the head builds on Mono and keeps PublishTrimmed=false. WebAssembly — NativeAOT emits a native binary for a desktop OS and does not apply; the wasm analogue is mono's own RunAOTCompilation, a separate feature that is not enabled.

Prerequisites

  • .NET SDK 10.0 or later — developed against 10.0.400.
  • Windows head — net10.0-windows, Direct2D.
  • Linux head — net10.0, X11 clipboard and input coordination.
  • Android head — the android workload; net10.0-android36.0, minimum SDK 24, android-arm64 plus android-x64.
  • WebAssembly head — the wasm-tools workload. It publishes trimmed on every publish path; publishing this app untrimmed crashes the mono runtime at boot. CI has not built this head since 2026-09-14 — see Continuous integration.

The desktop heads still declare four configurations — Debug-Windows, Release-Windows, Debug-Linux, Release-Linux — beside plain Debug/Release. Directory.Build.props decomposes them; without it a -c Release-Linux publish builds unoptimised and with neither RELEASE nor LINUX defined.

The suppression list predates the package move

Directory.Build.props carries a suppressed-warning list — CS8602, CS8618 and CS8625 — with a documented reason for every code. It was measured against a clean rebuild of all five solutions rather than copied from elsewhere, and it attributes all three codes to component sources, almost all of them in Broiler.Dom.Html. That measurement is dated 2026-09-02, when the components still compiled here from submodules; they are packages now, and the file's own instruction to re-measure after a dependency change has not yet been followed.

CS8601, CS8603, CS8604 and CA1416 are suppressed only in src/Broiler.App.Android, the vendored .NET for Android glue, rather than repository-wide — so the same code newly introduced in Broiler.Writer.Core would still be reported.

NU1504, which this page used to call the one warning a clean build still emitted, is fixed upstream: it came from a duplicate Microsoft.SourceLink.GitHub reference in a nested Broiler.DOM checkout.

Known issues

The README records the three issues this page used to list — duplicate compilation, a nested Broiler.DOM gitlink pinned off main, and NU1504 — as fixed upstream. What is open now:

  • The test jobs fail on main. Both CI runs on 2026-09-30 failed; on 954a057 the failures are Tests (Linux) and Tests (Windows). The last green run on main was 2026-09-24.
  • The WebAssembly head is not built by CI, and whether it currently builds is unknown. The README still describes it as a working head.
  • Linux window-manager close skips the unsaved-changes prompt — see Dialogs.
  • The README lags the repository — submodule instructions, solution counts and a Solution manifest CI job that ci.yml no longer has.

Continuous integration

ci.yml runs on every push to main and every pull request:

  • Build — the Windows head on windows-latest, the Linux head on ubuntu-latest.
  • Tests — the suite on both hosts.
  • Android head — a separate job, since it pays for the android workload.
  • Publish (NativeAOT) — Release-Windows and Release-Linux with PublishAot=true, because AOT is the one build mode that fails on reflection the rest of the build accepts.
  • WebAssembly head — commented out since 32aadaa (2026-09-14), "until WebAssembly head is migrated" from submodules to NuGet packages.

publish.yml replaced the old release workflow. It is dispatch-only and builds the Windows and Linux Writer with NativeAOT and the Android Writer as a release-signed app bundle and APK — Mono, not NativeAOT, on Android — and drafts a GitHub pre-release carrying them. Nothing is public until someone publishes the draft by hand. There is no WebAssembly output. Each run takes the next preview number past every earlier writer-v* tag, so numbers only increase, and the preview number becomes the Android versionCode so each release installs over the one before.

Component · Integration

Broiler.Documents

Reads and writes rich-text interchange formats to and from a UI-free document model. Applications compose a codec catalog explicitly, codecs probe bounded byte prefixes, and a read returns a best-effort document plus diagnostics for everything it skipped or approximated.

0.1.0-preview.1 8 packages Apache-2.0 Untrusted document input

Packages

Eight packages ship. All target net10.0, ship XML documentation and a .snupkg, and are built deterministically with SourceLink. There is no meta-package — add a package per format you actually read or write.

The PDF codec is built, tested — and deliberately not published

Broiler.Documents.Pdf is IsPackable=false and registered in no application catalog

It is a base PDF codec — logical text import from ISO 32000-1 files and a deterministic PDF 1.7 writer, built only from what this repository implements itself, with no third-party runtime dependency and no bundled font or codec asset. Syntax, cross-references, object streams and the Flate / ASCIIHex / ASCII85 / RunLength filters are implemented. Every remaining PDF technology is detected, skipped with its own stable diagnostic, and reachable by composing a reviewed implementation into PdfCodecServices.

It stays unpacked and unregistered until the roadmap's read-preview and write-preview gates pass. The document CLI does not compose it either — a CLI that registered it would ship the capability the gates exist to hold back. IP and licensing requirements in that roadmap are engineering release controls, not a legal opinion; patent freedom-to-operate and reciprocal-license decisions require approval by a qualified legal reviewer.

Per-format conformance is documented, not implied

Each codec has a conformance document that is the authoritative statement of what it honours, approximates, ignores and skips — with the tests that exercise each category named. The RTF document, for example, tabulates the control words in each category and states two properties outright: the reader is total (never throws on malformed input) and safe by default.

The DOCX reader is a good illustration of what "best-effort plus diagnostics" means in practice. Tables are walked recursively so their paragraphs are read rather than dropped, then flattened into their cell paragraphs in row-major order with a docx.table.flattened diagnostic — because RichTextDocument has no table shape, and layout tables are how CV and letterhead templates hold their entire text. Dropping them silently would lose the document; flattening them without saying so would be a lie about fidelity.

A CLI built to be driven by a test system

Broiler.Documents.Cli creates, edits, converts, renders and compares documents. Every command has a --json form, and the exit code is a documented contract.

The two commands the rest of it exists to support both answer the same question — where are the gaps in these codecs — and both answer it structurally first, in pixels only when that is what you actually need to know:

round-trip through every format
broilerdoc roundtrip report.docx --via docx --via odt --via rtf --via html --via markdown
compare two documents, structurally or as pixels
broilerdoc compare a.docx b.docx --render --continuous --diff diff.png --tolerance 2

Component constraints

  • Target .NET 10 only.
  • No third-party runtime dependencies — including for PDF.
  • Abstraction assemblies stay platform-neutral, safe-code compatible, trimming-friendly and AOT-friendly.
  • No hidden global codec registration. There is no process-wide registry and no module initializer.

Security

The codecs parse untrusted input

RTF control words, Open XML and OpenDocument packages, HTML, and PDF object graphs all cross a parser boundary and must be treated as security-sensitive. No fuzzing campaign, dependency scan or independent security audit is recorded for this revision. Read limits and RTF sanitization are specified in ADR 0004.

Twelve ADRs

Eight of the twelve are PDF decisions — scope and delivery, request/result and commit semantics, security and privacy, pagination units and fonts, standards and IP provenance, and the base-implementation-plus-composed-extensions model. The other four fix component topology, document-model ownership and promotion, the codec contract and signature probe, and the RTF first-release subset.

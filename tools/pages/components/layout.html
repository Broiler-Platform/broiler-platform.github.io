Broiler.Layout

A CSS box-model and layout engine that knows nothing about graphics backends. It takes a DOM and computed styles and produces geometry; painting, resource acquisition, HTML parsing and platform UI all stay in their own assemblies.

Re-review required net10.0 Apache-2.0 Own repository since 2026-09-09

The public seam

The public API is deliberately small: the host abstractions ILayoutEnvironment, ILayoutFont and ILayoutImageLoader, their value types, and the renderer-neutral HTML metadata types used to construct a layout input. The concrete box tree and the layout algorithms are internal.

Layout consumes only Broiler.CSS and Broiler.CSS.Dom, Broiler.Dom, the backend-neutral Broiler.Graphics primitive layer, and the BCL. Nothing else.

ILayoutView is public too, but it is a contract a consumer implements and injects, not one this component fills — and nothing in any Broiler component implements it today. A consumer that injects no view reads no engine geometry.

Eleven friend assemblies, locked by a test

Eleven assemblies have deliberate access to internal layout state. The authoritative list is the InternalsVisibleTo set in Broiler.Layout.csproj, and LayoutArchitectureTests pins it exactly, so a new grant requires an explicit boundary decision rather than an InternalsVisibleTo line nobody notices. (The README's own table still shows nine and defers to the project file.)

Broiler.HTML.Headless, a friend until recently, is gone — the project was deleted from Broiler.HTML. Facade and application assemblies otherwise consume owned projections instead of traversing the internal tree — Broiler.HTML.Image delegates canvas-background resolution to orchestration, and the WPF app consumes dev-console snapshots. Reducing this surface further, as consumers move onto owned projections, is tracked work.

What is still open

Resource hardening

  • Establish CPU, allocation, nesting and document-size baselines for malformed and adversarial layout inputs.
  • Add stress and fuzz coverage for deep trees, extreme numeric values, large inline runs, tables, grid/flex interactions, anchor positioning and repeated relayout.
  • Define host-enforceable budgets or cancellation points wherever measurement shows unbounded work.

Active layout correctness

  • Close the remaining absolute-position static-position and self-alignment WPT clusters.
  • Complete vertical-grid fit-content and baseline behaviour, plus the open multi-column cases.
  • Finish position-try fit geometry, state/cascade handling and flip tactics.
  • Keep focused unit and architecture checks, plus the affected WPT pixel and reftest clusters, as CI gates for each correction — roadmap status text is not behaviour evidence.

Review status

The recorded approval no longer covers current source

The first-preview review targets commit 6eaa76cc8fbe753ad2ba4db9f570f66256306c55 (2026-07-01). The component has changed substantially since then, so that approval must not be treated as covering the current checkout or a broader release. A new release needs source review and a new attributable human decision, plus dependency/license review and recorded static-analysis and vulnerability-scan evidence — the first item on the component's roadmap. No such re-review is recorded for any of the preview packages since published to nuget.org.

Build and test

Broiler.Layout is no longer in-tree anywhere. Since 2026-09-09 it has had a repository of its own, Broiler-Platform/Broiler.Layout, moved out of Broiler.Browser, which no longer vendors it; the aggregate repository deleted its in-tree copy and now carries Layout as a submodule. It builds standalone, and every dependency — the Broiler packages included — restores from nuget.org.

standalone
git clone https://github.com/Broiler-Platform/Broiler.Layout.git
dotnet build Broiler.Layout.slnx -c Release
pwsh -File eng/run-tests.ps1 -Configuration Release

Broiler.Layout is published to nuget.org as a single package, currently at 0.1.0-preview.10 in consumers' pins; the numbers below preview.6 were spent on the retired GitHub Packages feed. CI builds and tests Release on Ubuntu and Windows with a floor on the executed test count, then packs and verifies the package.

Broiler.Layout.Tests moved with the component and runs in its own repository, which records no test count. The last figure published for it — 1,317 tests, green — comes from the aggregate repository's older unit-test status document, from before the move. See unit-test status.

Broiler.Layout

A CSS box-model and layout engine that knows nothing about graphics backends. It takes a DOM and computed styles and produces geometry; painting, resource acquisition, HTML parsing and platform UI all stay in their own assemblies.

Re-review required net10.0 Apache-2.0 In-tree, not a submodule

The public seam

The public API is deliberately small: the host abstractions ILayoutEnvironment, ILayoutFont and ILayoutImageLoader, their value types, and the renderer-neutral HTML metadata types used to construct a layout input. The concrete box tree and the layout algorithms are internal.

Layout consumes only Broiler.CSS and Broiler.CSS.Dom, Broiler.Dom, the backend-neutral Broiler.Graphics primitive layer, and the BCL. Nothing else.

Ten friend assemblies, locked by a test

Ten assemblies have deliberate access to internal layout state. The exact set is pinned by LayoutArchitectureTests, so a new grant requires an explicit boundary decision and a documentation update rather than an InternalsVisibleTo line nobody notices.

Friend assemblyCompatibility need
Broiler.HTML.DomParses, serializes and visits renderer box trees
Broiler.HTMLSelection, hit-testing and context-menu interaction over laid-out boxes
Broiler.HTML.OrchestrationProjects computed style, invokes layout, builds paint fragments
Broiler.HTML.HeadlessProduces the live geometry snapshot through ILayoutView
Broiler.HtmlBridge.DomSupplies the visual-viewport scale around geometry snapshots
Broiler.DevConsoleConverts the internal tree into renderer-independent diagnostic snapshots
Broiler.WptScoped native anchor placement around final WPT renders
Broiler.Layout.TestsExercises the internal layout kernel directly
Broiler.Cli.TestsCharacterizes renderer integration and internal box state during the preview compatibility window
Broiler.DevConsole.TestsCharacterizes diagnostic snapshots with constructed boxes

Facade and application assemblies consume owned projections instead of traversing the internal tree — Broiler.HTML.Image delegates canvas-background resolution to orchestration, and the WPF app consumes dev-console snapshots. Reducing this surface further, as consumers move onto owned projections, is tracked work.

What is still open

Resource hardening

  • Establish CPU, allocation, nesting and document-size baselines for malformed and adversarial layout inputs.
  • Add stress and fuzz coverage for deep trees, extreme numeric values, large inline runs, tables, grid/flex interactions, anchor positioning and repeated relayout.
  • Define host-enforceable budgets or cancellation points wherever measurement shows unbounded work.

Active layout correctness

  • Close the remaining absolute-position static-position and self-alignment WPT clusters.
  • Complete vertical-grid fit-content and baseline behaviour, plus the open multi-column cases.
  • Finish position-try fit geometry, state/cascade handling and flip tactics.
  • Keep focused unit and architecture checks, plus the affected WPT pixel and reftest clusters, as CI gates for each correction — roadmap status text is not behaviour evidence.

Build and test

Broiler.Layout is the one component with no standalone repository: it lives in the aggregate Broiler checkout, and Broiler.Browser vendors it as ordinary tracked files. Build it from the aggregate repository root.

from the aggregate root
dotnet build Broiler.Layout/Broiler.Layout/Broiler.Layout.csproj
dotnet test  Broiler.Layout/Broiler.Layout.Tests/Broiler.Layout.Tests.csproj

Broiler.Layout.Tests is the aggregate repository's largest green xUnit suite — 1,317 tests at the last recorded measurement. See unit-test status for what the rest of the suite reports.

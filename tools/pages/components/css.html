Scope — and what belongs elsewhere

This component owns CSS syntax, selectors, cascade, computed values, and the DOM-facing style service. Everything downstream of a computed value belongs to its own owner:

  • Layout — used values, box geometry, hit testing → Broiler.Layout
  • Painting — how a computed value becomes pixels → Broiler.HTML and Broiler.Graphics
  • CSSOM JavaScript wrappers and live identity → HtmlBridge
  • Browser timelines and animation scheduling → the browser host

What is still open

The CSS extraction and the renderer/bridge cutover are both complete; their history lives in Git rather than in the roadmap. Three items remain.

Device-pixel and high-DPI length handling

CssLengthParser.cs still marks the px conversion path for high-DPI follow-up. The open question is a layering one — which layer owns CSS-pixel-to-device-pixel conversion — and the placeholder adjustment has to go with the answer.

Exit gate:

  • CSS parsing remains deterministic and platform-neutral.
  • Computed lengths are covered at more than one device scale.
  • Broiler.HTML consumes the result without applying the scale twice.

User-agent display defaults that depart from the HTML stylesheet

CssUserAgentDefaults.DisplayValues maps each tag name to one display value, and departs from the HTML Standard's user-agent stylesheet in three places: dialog is always none, because a one-value-per-tag table cannot express dialog:not([open]); basefont has no entry, because Broiler.Dom.Html does not yet parse it as a void element; and rp has no entry, because Broiler.HTML has no ruby layout and paints the rp parentheses as the only separator. Broiler.HTML's own defaults make the same two choices, so both sheets change together.

Exit gate:

  • An open dialog computes to block and a closed one to none for every consumer of the shared defaults.
  • basefont and rp are none in both sheets, and the tests that pin their absence are replaced.

Build and test

There is no nested checkout any more. Broiler.CSS.Dom's dependency on the DOM is the Broiler.Dom package, and every dependency restores from nuget.org, with versions pinned in Directory.Packages.props.

standalone
dotnet build Broiler.CSS.slnx -c Release
pwsh -File eng/run-tests.ps1 -Configuration Release

CI builds and tests Release on Ubuntu and Windows, then packs and verifies both packages. Publishing goes to nuget.org only, at one past the highest preview either package has ever had there — never below a floor that records the numbers spent on the retired GitHub Packages feed.

Notes

Broiler.CSS used to reach its nested DOM checkout through a $(BroilerDomPath) property hook so a consumer could avoid compiling the DOM twice. With the nested checkout replaced by the Broiler.Dom package, that hook is obsolete — see repository topology for where nesting still exists.

The absolute-length fix in ParseToPixels — pt, pc, in, cm, mm and Q used to answer "not a length", which broke the border shorthand — is no longer a pending patch. It landed in this repository as 8db920a, and the reftest suite's patch list is empty.

Broiler.HTML

The renderer: a modular .NET HTML/CSS engine split into focused assemblies for parsing, CSS processing, layout integration, painting and image generation — plus a cross-platform command-line renderer and the pixel-diff tooling that makes comparisons reproducible.

Approved, conditions Apache-2.0 + BSD-3-Clause Derived from HTML Renderer

Origin and independence

Broiler.HTML is derived in part from HTML Renderer, created by José Manuel Menéndez Poo and developed by Arthur Teplitzki and other contributors. That project provided the original renderer architecture and implementation from which Broiler.HTML evolved. Inherited material remains subject to the BSD 3-Clause License and its retained copyright notices.

It has since been reorganized into separate parsing, CSS, layout, graphics, image, orchestration and platform assemblies, with substantial new and modified code — much of that later work created with AI coding tools under maintainer direction.

Broiler.HTML is maintained independently. It is not an official version, continuation or release of HTML Renderer, and the upstream authors have not reviewed or endorsed it.

Public API highlights

  • Broiler.HTML.Image.HtmlRender — renders HTML to in-memory bitmaps, PNG bytes and files.
  • Broiler.HTML.Graphics.HtmlRender — renders HTML to BBitmap instances, encoded bytes, files and renderer command lists.
  • Broiler.HTML.Tool — a cross-platform command-line renderer plus image-diff reporting.
  • Broiler.HTML.Image.PixelDiffRunner — compares rendered output to a baseline image.
  • Broiler.HTML.Image.MismatchClassifier — classifies visual mismatches for compliance triage.
  • Broiler.HTML.Adapters.RAdapter — the backend extension point for graphics, fonts, images, clipboard and context-menu services.

The command-line renderer

Source/Broiler.HTML.Tool renders HTML to PNG or JPEG from Windows, Linux or macOS. For local HTML files the CLI automatically uses the source file as the base URL, so relative stylesheets and images resolve consistently.

render a page
dotnet run --project Source/Broiler.HTML.Tool -- \
  --input ./page.html --output ./page.png --width 1280 --height 720

dotnet run --project Source/Broiler.HTML.Tool -- \
  --html "<html><body><h1>Hello</h1></body></html>" \
  --output ./hello.jpg --format jpeg --width 800 --height 600
compare against a reference screenshot
dotnet run --project Source/Broiler.HTML.Tool -- compare \
  --actual ./broiler.png --baseline ./chromium.png \
  --diff-output ./diff.png --json-output ./report.json

Other arguments: --auto-size with --max-width/--max-height, --quality for JPEG, --base-url for inline markup, and --font [Alias=]<path> to register deterministic fixture fonts such as WPT Ahem.

A repository-local WPT runner

Broiler.HTML carries its own Playwright-based runner for local web-platform-tests checkouts. It is distinct from the aggregate repository's two WPT suites — this one is scoped to the non-JavaScript corpus and lives with the renderer.

  • Discovers HTML/XHTML cases while skipping files that appear to depend on JavaScript
  • Can inventory the full non-JS corpus without rendering, via --scan-only
  • Applies the checked-in exclusion manifest at scripts/wpt/non-js-exclusions.json
  • Renders each case through the Broiler CLI and captures a Chromium reference with JavaScript disabled
  • Compares with PixelDiffRunner / MismatchClassifier and writes per-test diff artifacts plus summary.json and summary.md
prepare and run
npm install
npm run wpt:install-browsers
npm run wpt:prepare -- --output ./artifacts/wpt-source

npm run wpt:run -- --wpt-root ./artifacts/wpt-source \
  --include css/CSS2 --include css/css-backgrounds --include html/rendering \
  --limit-per-include 2 --width 800 --height 600

Each selected case gets a shared timeout budget across Broiler rendering, Chromium capture and image comparison — 30,000 ms by default, adjustable with --test-timeout-ms or BROILER_WPT_TEST_TIMEOUT_MS. Timed-out cases are recorded as failures in the summary rather than hanging the batch.

Build and validation

build
cd Source
dotnet build Broiler.HTML.slnx
dotnet test  Broiler.HTML.slnx

What dotnet test means here

The solution contains no checked-in .NET test projects yet, so dotnet test acts as a repository validation command rather than a substantive renderer test suite. The checked-in automated tests are the Node ones under scripts/wpt/*.test.mjs, run with npm test.

Known structural issue

Broiler.HTML still uses the pre-src/ layout

It spells its top-level Broiler.Media and Broiler.Graphics references in the flat layout those components used while they were vendored inside the monorepo. Both now publish under src/, so the references as written resolve nowhere, and consuming repositories carry a Directory.Build.targets that rewrites exactly those two references onto the top-level checkouts. Those rewrites — and the solution generator's $staleLayoutMappings table — drop out once this component follows the others into src/.

Preview status

The recorded review approves the component for first preview only, with conditions: renderer paths are not hardened for hostile HTML/CSS, and obsolete and transitional APIs remain. Passing tests or compliance cases does not replace source-level human review and is not a security guarantee.

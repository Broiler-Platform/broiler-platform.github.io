Broiler.CSS

CSS parsing and the cascade, split cleanly in two: a dependency-free syntax layer that knows nothing about documents, and a DOM-facing layer that resolves selectors and computed values over the canonical tree.

Approved for first preview net10.0 Apache-2.0 2 assemblies

What it contains

AssemblyOwns
Broiler.CSSCSS syntax, rules, selectors, declarations, values, diagnostics, parsing and serialization. No document dependency.
Broiler.CSS.DomSelector matching, cascade, computed values and DOM-facing style services over Broiler.DOM.

Scope — and what belongs elsewhere

This component owns CSS syntax, selectors, cascade, computed values, and the DOM-facing style service. Everything downstream of a computed value belongs to its own owner:

  • Layout — used values, box geometry, hit testing → Broiler.Layout
  • Painting — how a computed value becomes pixels → Broiler.HTML and Broiler.Graphics
  • CSSOM JavaScript wrappers and live identity → HtmlBridge
  • Browser timelines and animation scheduling → the browser host

What is still open

The CSS extraction and the renderer/bridge cutover are both complete; their history lives in Git rather than in the roadmap. Two items remain.

Device-pixel and high-DPI length handling

CssLengthParser.cs still marks the px conversion path for high-DPI follow-up. The open question is a layering one — which layer owns CSS-pixel-to-device-pixel conversion — and the placeholder adjustment has to go with the answer.

Exit gate:

  • CSS parsing remains deterministic and platform-neutral.
  • Computed lengths are covered at more than one device scale.
  • Broiler.HTML consumes the result without applying the scale twice.

Preview review

The recorded human review applies to a specific revision. Before a new preview claim, the changes since that revision have to be reviewed and HUMAN_REVIEW.md updated with the exact commit and scope. The current record approves the component for first preview, with dead and transitional code and preview instability recorded as accepted limitations.

Build and test

The repository carries a nested Broiler.DOM checkout so it builds standalone. Initialise it first.

standalone
git submodule update --init --recursive
dotnet build Broiler.CSS.slnx
dotnet test Broiler.CSS.slnx

Notes

Broiler.CSS is one of two components that already avoid the platform's duplicate-compilation problem: it reaches its dependency through a $(BroilerDomPath) property hook rather than a literal relative path, so a consumer can point it at the top-level checkout instead of compiling the nested copy a second time. That hook is the pattern the other components are expected to adopt — see repository topology.

One CSS fix currently sits outside the pinned pointers as a pending change — resolving absolute length units in ParseToPixels, which belongs to the reftest suite's work rather than to the pixel-gap documents.

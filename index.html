Managed code · .NET 10 · Apache-2.0

A browser engine, a word processor and an IDE — written in managed .NET.

Broiler is a stack of independently released .NET 10 components — DOM, CSS, layout, graphics, media, input, a retained-mode UI toolkit and a JavaScript engine that compiles to IL — and the three applications composed from them. No native engine is embedded, and no component pretends to be finished.

First preview — evaluation, testing and contribution only

Public APIs, repository layout and persisted formats are unstable and may change without notice. Substantial portions of Broiler were developed with AI assistance. No component is human-approved for preview use until its HUMAN_REVIEW.md names a reviewer, a reviewed commit, evidence and a decision — and most of those records are deliberately PENDING. Broiler.JS is not a security sandbox. Do not use this preview for production, security-critical or safety-critical work. How review status is recorded →

The stack

Everything above the operating system is managed code

Each tier depends only on the tier below it, and the direction is enforced by architecture tests rather than convention. Applications compose the backends they present with; abstractions never reference an implementation.

Components

Eleven components, released independently

Every reusable component is its own repository, its own solution, its own CI and its own NuGet packages — versioned in lockstep at 0.1.0-preview.1 during the preview. The applications are not published.

Broiler.DOM

Dependency-free DOM plus HTML tokenization, tree building and serialization. The only mutable tree in the stack.

Broiler.CSS

CSS syntax, selectors, declarations and diagnostics, plus selector matching, cascade and computed values over the DOM.

Broiler.Layout

Graphics-independent CSS box-model and layout engine. Ten friend assemblies, locked by an architecture test.

Broiler.Graphics

Bitmaps, canvas, deterministic CPU raster, text and render lists — plus Direct2D, OpenGL, Vulkan, EGL and Canvas backends.

Broiler.Media

Decode-first image, audio and video: PNG/APNG, JPEG, BMP, GIF, WebP, WAVE PCM, and Windows MP4 through Media Foundation.

Broiler.Input

Device discovery, lifecycle, timing, bounded delivery and capture leases, with Windows, Linux evdev and Android providers.

Broiler.HTML

The modular renderer, split into parsing, CSS, DOM, orchestration, rendering, graphics and image assemblies.

Broiler.JS

JavaScript compiled to .NET IL at runtime, validated against test262. Carries DateTime, Regex and Unicode.

Broiler.UI

56 packages: one contract and one Standard implementation per control, with real break-out OS windows and owner-drawn chrome.

Broiler.Documents

A UI-free rich-text model and the RTF, DOCX, ODT, HTML, Markdown and (gated) PDF codecs, with a scriptable CLI.

Broiler.VM

A NativeAOT-compatible host for verified bytecode profiles. Implemented and evidenced; every milestone unaccepted until a human reads it.

Evidence, not claims

Every number on this site names its corpus and its command

Broiler's documentation treats a passing test as evidence about one corpus at one revision, never as a statement that a component is correct, secure or complete. The figures below are the ones the repository actually records — including the uncomfortable ones.

51 WPT pixel gaps open, each with an owner and an exit gate — beside 50 fixed and 17 where the golden image, not Broiler, is wrong
167 HTML 5.2 suite cases, 175 of 176 coverage items covered or classified, 0 quarantined
47 / 116 Privacy-test-page probes Broiler answers where Chromium does — 69 measured platform gaps
0 % Code units certified by a named human in the one component that has adopted per-unit assurance

Two independent WPT suites

The golden-image suite scores Broiler against a Chromium screenshot; the reftest suite renders both the test and the reference WPT declares, with no second engine involved. Their pass rates are deliberately not comparable, and each is blind to what the other catches.

How the two suites differ →

Real pages, measured honestly

The real-world suite renders Google, Wikipedia, GitHub, MDN, heise, 7-Zip, Hacker News and W3C three ways — Chromium, Broiler live, and Broiler replaying Chromium's final DOM — so a bad result can be attributed to loading, scripting or painting.

Assurance

“Human reviewed” is a record you can check

A component-level review record attests to a whole component at one commit, and goes out of date the moment the code moves. Broiler Code's Human Review workspace records the same attestation per source file, against a hash of the exact content reviewed, so a rebase does not expire a review and a revert restores one.

Coverage counts only files approved and unchanged since. A stale approval is reported separately and never counts. The number sits beside test262 and WPT as the measure of what a person has actually read.

review coverage
dotnet run --project Broiler.Code/src/Broiler.Code.Review.Cli -- coverage --root .

Provenance

Two upstream projects made this possible

Broiler's rendering lineage comes from HTML Renderer and its JavaScript-engine lineage from Yantra JS. Inherited HTML Renderer material remains under the BSD 3-Clause License with its copyright notices retained; Yantra JS material remains under Apache-2.0 with upstream history intact.

Broiler has diverged substantially and is maintained independently. It is not a continuation, official edition or release of either project, and neither upstream team is affiliated with it or endorses it.

Unicode-provided data retains its own terms. See THIRD_PARTY_NOTICES.md for complete provenance and license references.

Start here

Clone it, or take one component

The aggregate repository composes everything through recursive submodules. If you only want a piece — the layout engine, the UI toolkit, the image codecs — take the package instead.

the whole platform
git clone --recurse-submodules https://github.com/MaiRat/Broiler.git
cd Broiler
dotnet build Broiler.Browser/Broiler.Windows.Browser.slnx
one component
dotnet add package Broiler.Layout --prerelease
dotnet add package Broiler.UI.All --prerelease      # the whole UI toolkit
dotnet add package Broiler.Media.Image.Managed --prerelease
